# 对 “修改昵称” 用例的完整描述（群报数小程序）

参与者：小程序用户（主要参与者），群报数后台系统（次要参与者）
目标：用户在群报数小程序修改个人昵称
范围：群报数小程序系统
前置条件：用户已经登录群报数小程序
后置事件：用户昵称信息更新成功，系统保存用户资料修改记录

## 主事件流

1. 用户点击【我的】，系统加载并展示个人中心页面
2. 用户点击头像 / 昵称区域，系统进入个人资料编辑页面
3. 用户选中昵称栏，输入新昵称
4. 用户点击完成按钮，系统校验新昵称格式合规性
5. 系统向群报数后台提交昵称修改请求，更新用户昵称数据
6. 系统返回修改成功提示，刷新个人资料页面展示新昵称

## 备选事件流

1a：用户未登录

1. 系统跳转登录页面，用例结束

3a：新昵称输入为空

1. 系统提示昵称不能为空，停留在编辑页面，返回步骤 3

4a：新昵称包含违规敏感内容

1. 系统提示昵称含有违规内容，请重新输入，返回步骤 3

4b：新昵称长度超出限制

1. 系统提示昵称长度不符合要求，返回步骤 3

5a：网络异常，无法连接后台

1. 系统提示网络错误，修改失败，停留在编辑页面

5b：后台服务器异常

1. 系统提示修改失败，请稍后重试，用例结束

发生频率：按需触发

## 4. Sequence diagram 时序图（借书流程）

<img src="C:\Users\ASUS\AppData\Roaming\Typora\typora-user-images\1793363301611.png" alt="1793363301611" style="zoom:67%;" />

```plantuml
@startuml 借书时序图
actor 读者 as Reader
participant 前端系统 as Front
participant 图书服务 as BookService
participant 记录服务 as RecordService
database 数据库 as DB

Reader -> Front : 请求借书(ISBN)
Front -> BookService : 查询图书状态
BookService -> DB : select book by isbn
DB --> BookService : 返回图书信息
BookService --> Front : 返回图书是否可借

alt 图书可借且读者未超限
    Front -> RecordService : 创建借阅记录
    RecordService -> DB : insert borrow record
    RecordService -> DB : update stock -1
    DB --> RecordService : 操作成功
    RecordService --> Front : 借书成功
    Front --> Reader : 借书成功，告知归还日期
else 不可借 / 借阅超限
    Front --> Reader : 借书失败提示
end
@enduml
```
